BITÁCORA DE EVOLUCIÓN: MÓDULO CLIENTES SAAS (KSMART360)
==========================================================

Este documento registra las mejoras estructurales, técnicas y estratégicas realizadas
en el módulo de administración SaaS para transformar el sistema en un 
"SaaS Operating System" de nivel empresarial.

----------------------------------------------------------
FASE 1: VISIBILIDAD Y CONTROL CRÍTICO
----------------------------------------------------------
Objetivo: Eliminar la ceguera administrativa y dar control total sobre el negocio.

Implementaciones Técnicas:
- Telemetría de Actividad: Se añadió el campo 'last_activity_at' al modelo Empresa.
- Registro Automático: Middleware en el backend que detecta el uso de la API y
  actualiza la actividad de la empresa (con throttle de 15 min para performance).
- Métricas en Tiempo Real: Consultas SQL optimizadas para obtener conteos de:
    * Usuarios por empresa.
    * Ventas procesadas.
    * Productos en catálogo.
- Auditoría SaaS: Creación de la tabla 'saas_audit_logs' para rastrear cada acción
  realizada por los SuperAdmins (cambios de plan, suspensiones, etc.).
- Dashboard Ejecutivo: Nueva interfaz con KPIs de ingresos (MRR/ARR), tasas de
  conversión y alertas de vencimiento.

----------------------------------------------------------
FASE 1.5: SANEAMIENTO TÉCNICO (INGENIERÍA)
----------------------------------------------------------
Objetivo: Reducir deuda técnica y asegurar la escalabilidad del sistema.

Mejoras de Arquitectura:
- Desmantelamiento del Monolito: El archivo 'GestionEmpresas.js' (800+ líneas) fue
  dividido en componentes especializados:
    * useSaaSData (Custom Hook): Centraliza lógica de datos y fetching.
    * SaaSOverview: Dashboard de KPIs.
    * TenantsTable: Gestión de inquilinos.
    * TenantDrawer360: Vista profunda de cada cliente.
    * AuditLogsTable: Trazabilidad histórica.
- Hardening de Base de Datos: Aplicación de la Migración V41 para añadir índices
  estratégicos en la tabla de auditoría (empresa_id, fecha).
- Gestión de Timezones: Normalización forzada a UTC en todos los cálculos de 
  fechas para evitar errores de tipo naive/aware en entornos distribuidos.

----------------------------------------------------------
FASE 2: AUTOMATIZACIÓN Y COMUNICACIÓN (IMPLEMENTACIÓN INFRA)
----------------------------------------------------------
Objetivo: Implementar cimientos críticos para procesos autónomos y comunicación global.

Logros Técnicos:
- Estados Tipados: Creación de Enums centralizados (PlanType, AccessStatus, SaaSJobStatus)
  para eliminar magic strings y garantizar consistencia de estados.
- Migración V42: Creación de tablas 'saas_announcements', 'saas_jobs_registry' y
  columna 'is_protected' en empresas (Protección contra expiración accidental).
- TenantAccessService: Implementación de la "Fuente Única de Verdad" para control de
  acceso. Centraliza lógica de ID #1, protección, trial y suspensión manual.
- Middleware Read-Only: Actualización del enforcement de seguridad para bloquear
  mutaciones (POST/PUT/PATCH/DELETE) en tenants restringidos (402 Payment Required).
- Job Locking Service: Sistema de locks lógicos en base de datos con detección de 
  'Stale Locks' (>1h) para evitar ejecuciones concurrentes conflictivas.
- Auditoría Estructurada: Schema JSON fijo para eventos automáticos de sistema.

----------------------------------------------------------
